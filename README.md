## Что сделано

Это консольный проект по первому занятию — «Классы». В нём собраны все три задания: доработанный `Book`, хранилище книг с проверкой владельца и небольшая модель профиля пользователя.

### Задание 1

Класс `Book` дополнен:

- главным конструктором `Book(title, author, year)`;
- упрощённым конструктором `Book(title)`, делегирующим главному значения `"неизвестен"` и `0`;
- свойством `IsRead`;
- методом `Deconstruct(out string title, out bool isRead)`.

В `Program.cs` есть примеры для обоих конструкторов, инициализатора и распаковки книги.

### Задание 2

В `StudentBookStorage` добавлен метод `PutABook`. Он:

- не принимает неопределённую книгу;
- проверяет доступ тем же правилом, что и извлечение;
- не заменяет уже находящуюся в хранилище книгу;
- возвращает `true` только при успешном размещении.

`GetABook` работает по тому же правилу доступа. После извлечения книга удаляется из хранилища. В консоли видно и удачные операции, и случаи, когда доступ отклонён.

### Задание 3

Реализованы классы:

- `User` — пользователь с ID, ФИО, логином и хэшем пароля;
- `CommunicationChannel` — канал связи с ID и именем;
- `Contact` — контакт с ID, каналом связи и идентификатором;
- `UserProfile` — профиль, объединяющий пользователя и коллекцию контактов;
- `UserProfileService` — создание профилей, изменение ФИО, добавление контактов и получение краткой статистики через деконструктор.

В примере создаётся профиль, к нему добавляются почта и мессенджер, после чего выводится короткая статистика.

## Ожидаемый результат

Программа последовательно выводит:

1. три книги и результат деконструкции одной книги;
2. результаты размещения и извлечения книги владельцем и посторонним студентом;
3. краткую статистику профиля и два его контакта.

Ключевые результаты проверки доступа в задании 2:

- владелец успешно размещает книгу — `True`;
- другой студент не может её извлечь — `False`;
- владелец успешно извлекает книгу — `True`;
- неопределённая книга не размещается — `False`.

## Что пришлось решить по ходу работы

1. `PutABook` не должен принимать `null`, поэтому перед размещением книга проверяется отдельно.
2. Проверку владельца не хотелось дублировать. Для размещения и извлечения используется один закрытый метод `IsValidAccess`.
3. Одного контакта для нормального примера мало, поэтому профиль хранит коллекцию. Снаружи её можно читать, но нельзя подменить.
4. Открытый пароль в модели хранить неправильно. Здесь есть только `PasswordHash`; само хэширование не относится к этому заданию.

## Вопросы по выполненной работе

1. Следует ли сравнивать владельцев хранилища по имени, как в исходном примере, или правильнее добавить студенту уникальный ID и сравнивать по нему?
2. Нужно ли разрешать `PutABook` заменять уже размещённую книгу, либо хранилище должно принимать новую книгу только после извлечения старой?
3. Должен ли сервис профилей самостоятельно вычислять хэш пароля, или получать уже готовый хэш от отдельного сервиса авторизации?
4. Следует ли запрещать добавление двух одинаковых контактов в один профиль?
